# Внешняя приёмка

Этот документ описывает реальную проверку. Локальные fake callback/Telegram тесты
не закрывают пункты ниже. Результаты записываются в docs/VERIFICATION.md.

Policy 1.2.0 согласована владельцем и развёрнута в auto. Production и единственный
активный монитор в свежем Work получили общий критерий; старый монитор
приостановлен, обе его подписки неактивны. При последующих
изменениях границ политики отдельно согласовать расширение автоматических удалений.

1. В Cloudflare проверить именно Free, существующее потребление аккаунта и точный
   новый Worker. Применить SQLite class migration v1 через deploy. Проверить health,
   401 без токена, OAuth metadata, DCR → consent → PKCE → токен и server/discover.
2. Подключить новый Worker в ChatGPT Plugins через **Add custom MCP server**.
   Указать OAuth/DCR. Скопировать показанный точный redirect URI в OAUTH_REDIRECT_URIS,
   если отличается от стабильного callback. Авторизовать владельца. Scan/rescan:
   проверить семь tools и два Events. Данные комментариев и ключи в журнал не писать.
3. Начать Work на web либо Work + Cloud на desktop, загрузить policy 1.2.0,
   запросить обе подписки. Проверить events/subscribe и signed challenge.
   CALLBACK_HOSTS должен содержать **точный официальный hostname фактически
   выданного callback**, подтверждённый при настройке; без wildcard. Не выводить
   полный callback URL и signing secret. Если хост ещё не разрешён, подписка
   ожидаемо завершится CallbackEndpointError; добавить проверенный host и повторить.
   Если Work сообщает об отсутствии событий при наличии Events на странице плагина,
   выполнить «Обновить инструменты» в настройках и повторить обнаружение.
   После изменения схемы проверить доступность новых enum не только на сервере,
   но и в фактическом контексте Work. Если существующий Work остаётся на старой
   схеме, проверить свежий контекст и перенести монитор: сначала приостановить
   старый, подтвердить неактивность его подписок, затем создать замену и
   восстановить согласованный режим auto (unsubscribe переводит его в manual).
   После сетевого отказа проверить `events.callback_last_failure`: там нет URL/ключа.
   Для Workers используется public-only HTTPS fetch с обязательным
   global_fetch_strictly_public; фактический адрес проверяет runtime, дополнительно
   выполняется DNS preflight. Контракт и источники — в ARCHITECTURE.
4. Бот — администратор только нужной discussion supergroup с can_delete_messages.
   Проверить getChat.linked_chat_id через configure_moderation. Первый режим dry_run.
5. Пользователь публикует отдельный тестовый комментарий. Проверить принятый update,
   сохранённую ревизию, доставку стабильного eventId с 2xx и настоящий запуск Work.
   ChatGPT читает контекст и вызывает apply_moderation_decisions. dry_run не удаляет.
6. После отдельной явной команды владельца включить manual и выполнить сохранённое
   тестовое spam-решение по decision_id/ревизии. Подтвердить исчезновение именно
   тестового сообщения и status=deleted. Для подтверждения именно auto провести
   отдельный тест с новым актуальным решением, затем вернуть dry_run до приёмки.
7. Проверить нормальный текст, цену, критику и цитату спама: остаются. Отредактировать
   тестовый комментарий, убедиться, что старая ревизия отвергается. Отписаться,
   проверить отсутствие новых доставок и запланированных удалений.
8. Измерить CPU Free Worker для холодного webhook и холодного/тёплого MCP-вызова
   в production analytics/tail, отдельно от DO CPU. Локальное wall time не заменяет
   эти показатели. Проверить строки SQL, активное wall time DO и запас аккаунта.

Если Work/Events или изменяющие tools недоступны, остановить событийную приёмку.
Ручной сценарий через тот же OAuth MCP остаётся доступным. Не подключать polling,
Cron или платный inference как обход.

На 17.10.2026 исправленный callback прошёл настоящий signed challenge, обе
подписки активны. Новый и отредактированный комментарий запустили Work без ручного
запроса; сохранены allow/price_question и allow/spam_quotation. Режим после dry_run
переведён в auto по запросу владельца. Фактические результаты удаления, задержки,
CPU и оставшиеся эксплуатационные ограничения — в [VERIFICATION](VERIFICATION.md).
Следующее настоящее редактирование собственного теста автоматически получило
spam/engagement_spam и status=deleted/source=model; ручное исполнение не вызывалось.
Для auto согласованы режим сервера, инструкция задачи и поручение родительскому
Work. Внешний CPU реальных webhook — 2–3 мс, двух первых запросов изолятов — 2 мс.
