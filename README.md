# Telegram Moderator — модерация комментариев с помощью ChatGPT

Сервис помогает владельцу Telegram-канала удалять явный спам из комментариев. Он получает новые и отредактированные сообщения, передаёт их на анализ в ChatGPT и применяет решение через Telegram-бота.

В проекте реализован весь процесс: приём событий, хранение комментариев и их версий, запуск анализа, проверка решений перед удалением и журнал результатов.

## Как работает модерация

1. **Telegram сообщает о комментарии.** Webhook — HTTP-уведомление от Telegram — приходит на сервер. Сервер проверяет, что сообщение относится к разрешённой группе обсуждений, и сохраняет его.
2. **Событие запускает ChatGPT.** Через MCP Events сервер уведомляет подключённую задачу в ChatGPT о новом или изменённом комментарии. MCP связывает ChatGPT с инструментами сервиса: чтением контекста и передачей решений.
3. **ChatGPT оценивает смысл.** Модель получает актуальный текст и доступный сохранённый контекст публикации и ветки. Она возвращает одно из трёх решений: оставить, признать спамом или передать на проверку — с коротким объяснением.
4. **Сервер проверяет действие.** Перед удалением он заново проверяет разрешённую группу, текущую версию комментария, режим работы, срок действия решения и права бота.
5. **Бот выполняет действие, результат сохраняется.** В автоматическом режиме допустимое решение о спаме приводит к удалению. В журнале отдельно отражаются рекомендация, попытка и фактический результат.

Анализ выполняется в подключённом ChatGPT. Собственный сервер принимает события, хранит состояние и выполняет разрешённые действия; отдельный вызов платного API модели в этой реализации не используется.

## Как сервис отличает спам от разговора

Правило модерации учитывает цель сообщения и его связь с обсуждением. Спамом считается явное постороннее предложение читателям: реклама, продажа, набор людей или привлечение в другую группу, профиль либо личные сообщения.

Вопросы, критика, обычный разговор и рекомендации по теме остаются. Само наличие ссылки, цены или рекламной фразы не служит основанием для удаления.

Примеры под публикацией с обзором кафе:

| Комментарий | Решение |
| --- | --- |
| «Сколько стоит завтрак?» | Оставить: вопрос по теме. |
| «Обслуживание плохое, больше не пойду» | Оставить: негативный отзыв допустим. |
| «Мне прислали рекламу накрутки, как на неё пожаловаться?» | Оставить: автор обсуждает спам. |
| «Накрутим подписчиков, заказы в личку» | Спам: постороннее рекламное предложение. |

При неясном намерении или недостатке контекста модель оставляет сообщение на проверку. Ссылки и вложения не скачиваются; изображения и аудио не анализируются.

## Контроль действий и работа со сбоями

- **Учёт редактирования.** Если сервер уже получил новую версию комментария, решение для предыдущей версии отклоняется.
- **Ограниченная область работы.** Удалять можно только сохранённые комментарии из разрешённых обсуждений. Посты канала, защищённые авторы и сообщения с неподтверждённой принадлежностью к обсуждению защищены серверными проверками.
- **Контроль полномочий.** Текст комментария рассматривается как данные для анализа. Он не даёт модели права менять настройки, расширять область работы или удалять произвольные сообщения.
- **Повторная обработка.** Дубли событий и решений распознаются. Состояние фоновых операций сохраняется, для временных ошибок предусмотрены ограниченные повторные попытки с учётом ограничений Telegram.
- **Понятный результат.** В журнале сохраняются решение, причина и статус исполнения. Отправка запроса на удаление сама по себе не считается успешным удалением.

Для проверки на своём канале предусмотрены три режима:

| Режим | Поведение |
| --- | --- |
| `dry_run` | Показывает, что было бы удалено, и сохраняет сообщения. Первый запуск начинается с этого режима. |
| `manual` | Сохраняет рекомендации; удаление выполняется после подтверждения владельца. |
| `auto` | Исполняет новые допустимые решения о спаме автоматически. |

## Технологии и их задачи

| Технология | Для чего используется |
| --- | --- |
| **TypeScript и Hono** | Серверная логика, HTTP-маршруты, приём Telegram webhook и работа MCP-сервера. |
| **Cloudflare Workers** | Запуск серверной части без отдельного постоянно работающего сервера. |
| **SQLite Durable Object** | Хранение комментариев, их версий, настроек, подписок, фоновых задач и журнала решений. |
| **Durable Object Alarms** | Запуск сохранённых фоновых задач, повторных попыток и очистки старых данных. |
| **MCP SDK и MCP Events** | Инструменты для ChatGPT и уведомления, которые запускают анализ по событию. |
| **OAuth** | Авторизованный доступ владельца и подключённого ChatGPT к инструментам сервиса. |
| **Telegram Bot API** | Получение событий, проверка прав бота и удаление сообщений. |
| **Vitest** | Проверки правил обработки, повторных событий, редактирования, авторизации и ошибок внешних сервисов. |

Инфраструктура рассчитана на Cloudflare Workers Free в пределах его квот. Доступность событий и запусков анализа зависит от возможностей и лимитов подключённого аккаунта ChatGPT.

## Проверка и границы работы

В живой проверке 17–18 октября 2026 года подтверждён полный сценарий: событие от Telegram → запуск ChatGPT → решение → удаление тестового спама. Также проверены сохранение обычного вопроса и жалобы с цитатой рекламы. [Подробности проверки](docs/VERIFICATION.md).

Модерация выполняется **после публикации**: комментарий может быть виден до анализа. Если ChatGPT недоступен, решение просрочено или контекста недостаточно, сообщение остаётся. Срок ожидания решения — 30 минут. Изменение текста, которое Telegram ещё не доставил серверу, нельзя учесть при проверке версии.

Сервис рассчитан на одного владельца и явно выбранные группы обсуждений. Подключение требует Telegram-бота с правом удаления сообщений и аккаунта ChatGPT с поддержкой нужных событий.

## Локальная разработка

Инструменты: Node.js 24 и pnpm 11.15.1. Параметры окружения перечислены в [.dev.vars.example](.dev.vars.example); локальные значения и секреты хранятся вне Git.

```sh
pnpm install
node scripts/local-secrets.mjs
pnpm dev
```

```sh
pnpm check
```

`check` включает проверку типов, форматирования, границ модулей, тесты и сборку без публикации. Локальные тесты не подтверждают подключение настоящих Telegram и ChatGPT: для этого предусмотрена отдельная [внешняя проверка](docs/EXTERNAL_SMOKE.md).
